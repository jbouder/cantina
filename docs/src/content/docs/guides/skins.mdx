displays and the timeline. Six ship with Cantina, and a new one is two small
CSS files and an entry in a list.

## Pick a skin

Open **Settings** with the gear and choose under **Skin**, or pick one from
**View ▸ Skin**. The studio
changes at once, and the choice is remembered for next time.

Neon's edge pulses on the beat. **Reduce flashing** in Settings stills it,
and so does the system's *Reduce motion* setting.

## Write your own

This recipe makes **Ember**, a warm brown take on Classic with amber
displays. A skin only sets the tokens that differ from Classic; everything
else falls back to Classic's value. The [skin tokens](/reference/skin-tokens/)
page lists every token.

### 1. The shared palette

Create `packages/skins/tokens/ember.css`. This is the palette Cantina shares
with music-visualizer: frame, title bar, displays, keys, text, lights and
focus.

```css
/* Ember: the tokens both apps draw with. */
:root[data-skin="ember"] {
  /* Frame: the window chrome around everything. */
  --frame-hi: #6e4a3c;
  --frame: #3a2620;
  --frame-mid: #2e1e19;
  --frame-lo: #1a110e;
  --frame-edge: #080504;

  /* Title bar. */
  --title-on: #ff8a3d;
  --title-on-lo: #6b3315;

  /* Displays: readouts, meter backplates, lists. */
  --lcd-fg: #ffb347;
  --lcd-dim: #3a2408;
  --list-fg: #ffb347;

  /* Indicator lights. */
  --led-on: #ff8a3d;
  --led-off: #3a1d0e;

  /* Focus. */
  --focus: #ffd29a;
}
```

Then import it at the end of `packages/skins/tokens.css`:

```css
@import "./tokens/ember.css";
```

### 2. Cantina's own tokens

Create `ui/src/skins/ember.css` for the tokens only Cantina has: `--face`,
the flat color text sits on, the timeline's colors, and the colors that
follow the display and the lights. Classic's are green, so a skin with
another display color sets `--lcd-muted` (secondary text on a display) and
the on and selected states to match. Materials such as the window's shape
and the buttons' finish go here too; this skin keeps Classic's.

```css
/*
 * Ember: Classic's shape in warm brown, with amber displays. Only the
 * tokens that differ from Classic are set.
 */
:root[data-skin="ember"] {
  --face: #34221d;

  /* Timeline. */
  --tl-clip: #4d2a12;
  --tl-clip-edge: #ff8a3d;
  --tl-clip-selected: #6b3a18;
  --tl-wave: #ffc27a;

  /* Secondary text on the amber display. */
  --lcd-muted: #c98a2e;

  /* A key that is on, and the chosen one of several. */
  --state-on: #4a2408;
  --state-on-ink: #ffc27a;
  --state-selected: #a84a12;
  --state-selected-ink: #ffffff;
}
```

Import it in `ui/src/styles.css`, after the other skins:

```css
@import "./skins/ember.css";
```

### 3. Add it to the list

Add Ember to `SKINS` in `packages/skins/index.ts`. The picker in Settings,
the saved choice and the screenshot script all read this list. The preview
colors draw the swatch in Settings, and a test checks that they match the
skin's tokens: `--frame`, `--title-on`, `--lcd-bg`, `--lcd-fg`, `--silver`
and `--led-on`, falling back to Classic's.

Give it a **View ▸ Skin** item too: add `"skin-ember": { "label": "Ember", "checkable": true }`
to the actions in `ui/src/lib/actions.json` and put it in the Skin submenu.
A test fails until every skin has one.

```ts
{
  id: "ember",
  name: "Ember",
  beat: false, // true only if the skin's CSS reads --beat
  preview: {
    frame: "#3a2620",
    title: "#ff8a3d",
    lcd: "#000",
    lcdInk: "#ffb347",
    key: "#c4c4ce",
    led: "#ff8a3d",
  },
},
```

### 4. Check it

```sh
npm run check
```

This lints, checks that no color appears outside the skin files, checks
every skin's contrast and that its button states can be told apart, and
runs the tests, including the preview check.
Then look at it:

```sh
npm run dev              # open http://localhost:1420/?skin=ember
scripts/screenshot.sh ember "skin=ember" "skin=ember&settings"
```

## What every skin must keep

- **Sizes belong to the components.** Every key and display is 32 px; a skin
  changes their material, never their size.
- **Visible focus.** The focus ring is `2px solid var(--focus)`. Pick a
  `--focus` that stands out on both the frame and the buttons; on a light
  frame that means a dark or saturated ring.
- **Contrast.** `npm run check` fails below 4.5:1 for text, such as `--ink`
  and `--ink-dim` on `--face`, `--glyph` on `--silver`, `--lcd-fg` on
  `--lcd-bg` and `--sheet-ink` on `--sheet-bg`, and below 3:1 for the focus
  ring. Gradients cannot be measured, so `--face`, `--silver` and `--pbtn`
  must be the flat colors the surfaces average to.
- **States that differ.** A key that is on (`--state-on`), selected
  (`--state-selected`) or disabled (`--state-disabled`) must not pass for
  one of the others, so the check fails when two of the three fills are
  close in color. It also fails when the disabled fill is brighter than
  `--silver` or `--pbtn`: a key that cannot be used is never the brightest
  in its row. Each state's `-ink` needs 4.5:1 on its fill, 3:1 for
  disabled.
- **Fields that read as fields.** `--field-fg` and `--field-dim` need
  4.5:1 on `--field-bg`, and the field should not share the display's
  colors: a user must see at a glance what can be typed in.
- **Reduced motion.** Anything that moves on `--beat` must look still when
  it is 0, which it is under *Reduce motion* and Reduce flashing.
- **No colors outside skin files.** If a component needs a new color, add
  a token to Classic first and set it in each skin that should differ.
- **Light frames set `color-scheme: light`** so form controls and scroll
  bars match, as Brushed metal, Hi-fi and Toxic do.
